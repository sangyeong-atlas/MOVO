# Hyundai MOVO

**혼자일 땐 하루가 가벼워지고, 함께일 땐 서로가 편안해지도록 — 경로부터 픽업과 좌석까지 차 안의 이동을 하나의 여정으로 잇습니다.**

팀 **산경 아틀라스**의 차량용 앱 개발 공모전 제출 소스입니다. 차량용 Android 앱, 모바일 웹/PWA, 공통 Python 백엔드로 구성됩니다.

## 왜 차량용 앱인가요?

운전자는 메신저에 흩어진 픽업 위치·준비 상태·경유지 요청을 차량 화면으로 다시 옮겨야 합니다. MOVO는 모바일에서 함께 준비한 파티방을 차량에 연결하고, 운전자가 픽업·탑승·경로 변경을 확인하며 여정을 진행하게 합니다. 동승자는 자기 좌석과 픽업 지점을 선택하고, 이동 중 요청을 보내며, 하차 후 주차 위치와 기록을 확인합니다.

반복 출퇴근을 하는 운전자와 가족·친구·동료를 태우는 운전자가 주요 타깃입니다. 초대 링크를 통해 동승자가 참여하고, 저장한 코스와 크루를 다음 여정에 재사용하는 흐름을 제공합니다. MAU·재사용률은 아직 실측하지 않았으며, 차량 사전 탑재나 상용화가 확정된 제품은 아닙니다.

## 현재 구현

- 파티 생성, 계정별 초대·수락, 좌석 선택, 픽업·하차 위치, 준비·탑승 상태 공유
- 6자리 일회용 코드로 차량 연결, 차량 전용 토큰, SSE와 주기 조회를 통한 상태 복구
- 모바일 B안 12개 화면과 지도·5인승 좌석을 함께 보여주는 차량 화면
- 카카오 장소 검색, 네이버 Directions 공통 도로 경로와 경유지 추가 이동시간 계산
- 동승자 경유지 제안 → 운전자 승인 → 내비게이션 적용 결과 확인 → 코스 갱신
- Pleos STT·TTS 음성 조회, 메시지 읽기, 확인 후 저장하는 주차 메모
- 선택적으로 켜는 “헤이 모보” 호출어 대기, 주차 저장 ACK·재시도, 여정 완료 기록

**실제 차량 위치·자동 탑승 판정·물리 공조 제어는 미연동입니다.** 차량 이동과 좌석 공조는 시뮬레이터로 시연합니다. 내비게이션과 음성 SDK는 Pleos 서비스가 제공되는 환경이 필요합니다. 외부 지도 API가 설정되지 않았거나 실패하면 도로 경로·ETA를 실제 값처럼 생성하지 않습니다. [구현 범위와 제한](docs/IMPLEMENTATION.md)을 확인하세요.

## Pleos SDK 활용

| SDK | 버전 | 앱에서 사용하는 기능 |
|---|---|---|
| NaviHelper | 3.0.5 | 위치·경로·ETA/TBT 수신, 운전자 확인 후 목적지·경유지 전달, 적용 결과 확인 |
| SpeechToText | 3.3.1 | 한국어 ON_DEVICE 음성 입력, 여정 조회·경유지 제안·주차 메모 초안 |
| TextToSpeech | 3.3.1 | 음성 답변과 동승자의 빠른 메시지 읽기 |

Vehicle SDK, FusedLocation, Gleo AI는 현재 앱의 구현 의존성에 포함되어 있지 않습니다. 해당 연동은 향후 개발 범위입니다.

## 빠른 실행

### 1. 백엔드

저장소 루트에서 실행합니다. 기본 포트는 `8787`이며 새 체크아웃은 별도 DB를 만듭니다.

```sh
python3 backend/server_v2.py
```

기본 DB는 `backend/hopon.db`이며 Git에서 제외합니다. 다른 DB/포트가 필요하면 `HOPON_DB`와 `PORT` 환경변수를 지정하세요. 기존 사용 중인 서버·DB를 테스트에 재사용하지 마세요.

### 2. 지도 설정

```sh
cp backend/.env.example backend/.env.local
```

`backend/.env.local`에 본인의 키를 설정하고 백엔드를 다시 시작합니다. 키는 제출 파일에 포함하지 않습니다.

| 변수 | 용도 |
|---|---|
| `KAKAO_REST_API_KEY` | 서버의 실제 장소 검색 |
| `KAKAO_JAVASCRIPT_KEY` | 모바일 카카오 지도; 허용 웹 origin 등록 필요 |
| `NAVER_MAPS_CLIENT_ID` | 네이버 Maps API Key ID |
| `NAVER_MAPS_CLIENT_SECRET` | 네이버 Maps API Key; Directions 5/15 활성화 필요 |

카카오 JavaScript 키는 웹 지도에 전달되는 공개 브라우저 키입니다. REST 키·네이버 Secret은 서버에서만 사용합니다. 키가 없어도 앱과 서버는 실행되지만, 실제 장소 검색·도로 경로·도로 ETA 시연은 제한됩니다.

### 3. 모바일 웹

새 터미널에서 실행합니다. **루트의 백엔드를 공통으로 사용합니다.**

```sh
cd mobile
npm ci
npm run dev
```

브라우저에서 `http://localhost:5173`을 엽니다. 기본 화면은 실제 서비스 홈이고, `/?preview=1`은 예시 데이터가 있는 12개 화면 디자인 미리보기입니다. 두 사용자의 흐름은 서로 다른 브라우저 프로필/시크릿 창에서 확인합니다. 같은 Wi-Fi의 휴대폰은 Vite의 Network 주소를 사용하고 카카오 허용 origin도 그 주소로 등록합니다.

`mobile/backend/`는 이전 독립 구현을 보존한 호환 소스입니다. 이번 시연에서는 별도 실행하지 않습니다.

### 4. 차량 앱 설치·연결

Android SDK의 `platform-tools`를 PATH에 등록하고, **새 심사용 Pleos 에뮬레이터**를 실행합니다. 여러 기기가 연결돼 있다면 아래 명령에 `-s <심사용 기기 ID>`를 지정하세요.

```sh
adb install "apk/산경아틀라스_Hyundai MOVO_release.apk"
adb shell am start -n com.hopon.car/.MainActivity
```

모바일에서 파티 생성 → 계정 등록/로그인 → 초대·수락 → 여정 계획의 하단 **차량 연결 및 여정 진행** → **차량 연결 코드 생성**을 선택합니다. 차량 앱에서 서버 주소 `http://10.0.2.2:8787`과 6자리 코드를 입력합니다. 코드는 5분 동안 한 번 사용할 수 있습니다.

빠른 합성 여정은 루트에서 `python3 scripts/demo.py create`로 만들 수 있습니다. 출력되는 임시 계정·코드는 시연에만 사용하며, 생성된 세션 파일은 업로드하지 않습니다.

### 5. 권장 시연 순서

1. 두 브라우저에서 파티 생성·초대 수락·좌석과 픽업 위치 설정
2. 차량 페어링 후 픽업 시작 → 모바일 “나왔어요” → 차량 탑승 확인
3. 전원 탑승 후 출발 → 모바일/음성 경유지 제안 → 운전자 승인 → 적용 결과 확인
4. 음성 버튼으로 “여정 상태 알려줘”, “가는 길에 카페 들르자” 시연
5. 도착 → 주차 위치·메모 저장 → 서버 저장 확인 → 여정 마치기 → 모바일 기록 확인

“헤이 모보”는 설정에서 별도로 켜며 마이크·알림·다른 앱 위에 표시 권한이 필요합니다. 저전력 시스템 호출어가 아닌 STT 기반 대기 기능입니다. 권한 설정 화면이 없는 Pleos 개발 이미지에서는 환경별 추가 설정이 필요하므로 기본 시연은 음성 버튼으로 진행할 수 있습니다.

## 소스 빌드와 검증

Android SDK 경로는 `ANDROID_HOME` 또는 Git에서 제외되는 `local.properties`에 설정하고 `JAVA_HOME`은 JDK 17을 가리키게 합니다.

```sh
./gradlew :app:testDebugUnitTest :app:assembleDebug :app:lintDebug
python3 -m unittest discover -s backend -p 'test*.py'
cd mobile
npm run build
```

release는 `./gradlew :app:assembleRelease`로 빌드한 뒤 [서명 안내](docs/RELEASE.md)에 따라 서명합니다. 서명 키와 비밀번호는 저장소에 넣지 않습니다.

백엔드 테스트는 임시 DB와 임의 포트를 사용합니다. Android 기기 통합 테스트는 별도 서버 `8793`과 격리 환경이 필요하며, 사용 중인 앱을 삭제할 수 있는 자동 connected 테스트를 공유 에뮬레이터에서 실행하지 않습니다. [이번 제출 검증 결과](docs/VALIDATION.md)를 확인하세요.

## 폴더 구성

| 경로 | 내용 |
|---|---|
| `app/` | Kotlin 차량 앱과 단위·기기 테스트 |
| `backend/` | 공통 API, 상태 동기화, 지도 제공자 연동, 회귀 테스트 |
| `mobile/` | 모바일 B안, React/TypeScript, 정적 자산, 테스트 |
| `docs/contracts/` | API 계약 참고 자료 |
| `apk/` | 제출용 서명 release APK |
| `gradle/`, `gradlew*` | 재현 빌드용 Gradle Wrapper |

계약 문서에는 이전 버전 설명도 포함되어 있습니다. 최신 동작은 공통 백엔드 구현과 회귀 테스트를 기준으로 확인하세요. 개인 계정 정보, 실제 API 키, DB·세션, 개발 Git 이력, 원본 신청서는 포함하지 않습니다.
